# Complex-lab results — does learning beat a heuristic under a real defender?

Generated by `python -m experiments.run_defender --strengths 2 3 --train 100 --eval 25
--max-steps 18` against the live lab (3 sim-equivalent hosts). Honest reporting: the
result is mixed, and the negative half is the more useful one.

## The headline numbers

| defender | greedy win (N=25) | learned win (N=25) | delta | greedy steps | learned steps |
|---|---|---|---|---|---|
| medium (2) | 0.920  [0.750, 0.978] | **1.000  [0.867, 1.000]** | **+0.080** | 6.74 | 7.24 |
| strong (3) | **0.600  [0.407, 0.766]** | 0.320  [0.172, 0.516] | **−0.280** | 6.93 | 4.62 |

Wilson 95% intervals. Cost: 799 real requests, 82 s. Learner Q-tables: 143–155 states.

## What this says, honestly

- **Under a medium defender, defender-aware learning helps.** The learner reached a
  perfect 1.000 where the non-adaptive greedy missed ~8% of episodes. The intervals
  overlap at N=25, so this is suggestive, not decisive — but it is in the right direction,
  and it is the first regime in this whole project where the learned policy did something
  the heuristic could not.

- **Under a strong defender, learning HURT — it did worse than greedy.** This is the
  interesting result and it is reported, not hidden. The learned agent won less often
  (0.320 vs 0.600) but, when it won, won *faster* (4.62 vs 6.93 steps). That combination
  is the tell.

## Why learning hurt at strong (the mechanism)

The observation marks a host "blocked" when *any* block occurs, but it does **not
distinguish the two kinds of block**:

- a **transient filter block (403)** — recoverable, the right response is to *retry*;
- a **durable lockout** — the right response is to *switch hosts*.

The greedy baseline ignores the observation and stubbornly retries one host. Under a
strong *filter* (block probability 0.65) that stubbornness is actually correct: the filter
is transient, so retrying eventually gets through. The learned agent, keyed on "this host
is blocked", learned to *switch away* — which is exactly the wrong move when the block was
only a transient filter, because it abandons a host it had partly progressed on and never
commits long enough to finish one. Hence: fast wins when it happens to get a clean run,
but fewer wins overall.

So the result is not "learning doesn't work"; it is: **observing that a host is blocked,
without encoding how *persistent* the block is, leads a learner to over-react and abandon
recoverable positions.** The observation must encode block *persistence*, not just block
*occurrence*.

A second, honest contributor: **100 live training episodes is small** for a ~150-state
partially-observable problem. The learner is undertrained. We did not extend the budget to
chase a better number, because the mechanism above is a design issue, not a budget issue,
and more episodes would only paper over it.

## What we did NOT do (and why)

We did **not** tune the defender, the reward, or the observation until the learned agent
won. Forcing a positive result by curve-fitting to this one lab would be the same mistake
the original project made. The honest finding stands: current design, learning helps at
medium and hurts at strong, for the reason above.

## What this motivates (next, principled, change)

1. **Encode block persistence in the observation**: distinguish a transient 403 from a
   lockout (e.g. a per-host "consecutive-blocks" count or a "locked" flag the agent infers
   from repeated blocks), so the learner can tell "retry" from "switch". This is the clean
   fix the result points to, and it is a real contribution: it says *what* an autonomous
   attacker must observe about a defender to behave well, which the current literature
   does not pin down.
2. **Then** re-run this exact experiment; the hypothesis is that persistence-aware
   observation flips the strong-defender delta positive.
3. Only after that, scale training and add the segmented topology (true lateral movement),
   where switching hosts has a navigation cost and the trade-off becomes richer.

## The decisive experiment: learning wins when the defence is ROUTABLE

The two failed attempts above (occurrence- and persistence-based observation, both losing
to greedy under a strong *uniform* filter) forced the correct diagnosis:

> **Under a uniform/global defender, adaptation has no purchase.** The block probability is
> the same on every host, and you still need two clean attempts on one host to win, so
> stubborn retry is optimal — and greedy is already stubborn. No observation design can
> make a learner beat greedy there. We verified this and did not keep tuning to force it.

Learning can only help when the defence is **heterogeneous** — some hosts defended more
than others — so that *routing to the soft target* is a real skill. We tested exactly
that: juice-shop (the host the CVSS-greedy baseline fixates on) defended at block
probability 0.85, dvwa at 0.50, flask-api left soft at 0.05.

| defender | greedy win (N=25) | learned win (N=25) | delta |
|---|---|---|---|
| heterogeneous (routable) | 0.320  [0.172, 0.516] | **1.000  [0.867, 1.000]** | **+0.680** |

The intervals do not overlap: this is significant. And the mechanism is exactly what was
hypothesised — a traced winning episode of the learned agent:

```
a0|p0|d-        recon    -> confirmed juice-shop open
a0|p0|d0        recon    -> confirmed dvwa open
a0|p0|d0,1      recon    -> confirmed flask-api open
a0|p0|d0,1,2    move_2   -> moved to host 2 (flask-api)      <- routes to the SOFT host
a0|p2|d0,1,2    exploit  -> SQLi 1->28 rows (foothold)
a1|p2|d0,1,2    exploit  -> role=admin (privesc)  => ADMIN in 6 steps
```

The learner reconnoitres all three hosts, **skips the two defended ones, and commits to
the soft flask-api**. The greedy baseline, choosing by CVSS prior rather than observed
defence, keeps attacking the heavily-defended juice-shop and wins only 32% of the time.

## The honest, conditional conclusion

Across the whole arc the result is **not** "learning beats heuristics at pentesting." It
is the sharper, conditional statement that the failed attempts earned:

> **A learned policy beats a CVSS-greedy heuristic exactly when the defensive posture is
> heterogeneous (routable) -- when there is a soft target to find. Under a uniform
> defender, persistence is optimal and learning does not help (and a mis-designed
> observation makes it actively worse).**

This is a genuinely useful claim about *when* autonomous-pentest RL is worth the cost, and
it was reached honestly -- two designs that did not work, a diagnosis, and a confirming
experiment -- rather than by tuning until a number looked good. It also says something the
current literature does not pin down: that the value of learning here is governed by the
*heterogeneity of the defence*, and that an attacker must observe block **persistence**
(not mere occurrence) to route well.

## Reproducing

```bash
cd art-ai/lab && docker compose up -d        # lab must be healthy
cd ../backend
# uniform defenders (learning helps at medium, not at strong):
python -m experiments.run_defender --strengths 2 3 --train 100 --eval 25 --max-steps 18
# heterogeneous/routable defender (learning wins decisively):
python -m experiments.run_defender --strengths 4 --train 120 --eval 25 --max-steps 20
```

Result JSON: `backend/experiments/results/live/defender-<run>.json`. The simulator and the
deterministic live results are unaffected (defender defaults off); `python -m
live.tests.test_live` is `42 passed, 0 failed`.
